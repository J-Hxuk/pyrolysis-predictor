# 바이오차 물성·흡착성능 2-Stage 예측 프로그램 요구사항

> **개정 이력**
> - v1 (이전): 범용 폐기물 열분해 생성물·고체 특성·촉매 성능 예측 요구사항.
> - **v2 (현재)**: 연구 방향이 바이오차 **Stage 1 물성(BET·TPV)** 과 **Stage 2 흡착성능(qe)** 예측으로
>   변경됨. `Biochar_Complete_Project_v41.zip`(이하 v41) 도입에 맞춰 개정. 범용 기체·액체 조성,
>   작용기, 기타 촉매 성능 예측은 **당장 필수 구현 대상에서 제외**하되 확장 가능 구조는 유지한다.
>   v1 의 보안·데이터 무결성·누설 방지·모델 재사용 요구사항은 유효하므로 유지한다.

## 1. 목적과 기본 구성

실제 논문에서 정리한 바이오차 실험 자료를 학습하여, 새로운 원료·공정 조건의 **바이오차 물성**과
**흡착 성능**을 예측하는 연구용 프로그램을 개발한다. 예측은 두 단계로 나눈다.

- **Stage 1 (물성)**: 원료 조성과 열분해 조건으로 바이오차 물성을 예측한다.
  - BET 비표면적(m²/g): **우선 구현 대상**.
  - 총 공극부피 TPV(cm³/g): 별도 모델 검증 후 활성화(현재 보류).
- **Stage 2 (흡착성능)**: 바이오차 물성과 흡착 실험조건으로 평형흡착량 qe(mg/g)를 예측한다.
  - 신규 데이터셋을 별도 제작 중이며, **데이터 확정 전 머신러닝 모델을 학습하지 않는다.**

프로그램은 별도로 실행하는 학습·평가 코드와, 저장된 모델을 재사용하는 예측 웹앱으로 구성한다.
웹앱은 이용 중 모델을 학습하지 않는다. 학습과 추론을 분리한다.

주요 사용자는 연구팀원이며, 웹앱은 로그인 없이 이용한다. 사용자는 단일 조건을 입력하거나
Excel·CSV로 여러 후보를 제공하고, 예측 결과와 조건 비교를 화면에서 확인한다.

입력 변수와 단위는 v41의 `eval37/INPUT_CONTRACT_KO.md`를 우선 참고하여 코드 상수가 아닌
설정·계약 모듈로 관리한다.

## 2. 프로그램의 범위

### 2.1 포함하는 결과물

1. v41 패키지에서 **필요한 파일만 선택 추출**하여 읽고 점검하는 데이터 로더·검증 코드(원본 미변경).
2. Stage 1 BET 예측 모델의 학습·독립 평가(출처 그룹 분할) 및 버전 저장.
3. 학습 모델, 전처리 정보, 입력 규격, 단위·분석 basis, 검증 정보, 적용 범위를 함께 담은 모델 산출물.
4. 단일 입력과 파일 기반 일괄 입력을 받는 예측 웹앱(공학 분석 스타일 5개 화면).
5. 동일 원료에서 조건을 변화시키는 **조건 비교**와 예측 응답 곡선, CSV 결과 저장.
6. Stage 2 **확장 인터페이스**(입력 스키마·검증·학습 차단) 및 실측 등온흡착 **Langmuir fitting**.
7. 학습 실행·모델 활성화·앱 실행에 필요한 사용 설명.

### 2.2 구현 범위에서 제외하거나 보류하는 기능

- **보류(향후 활성화)**: Stage 1 TPV 예측 모델(학습 후보만 준비, 독립 검증 후 활성화).
- **보류(데이터 대기)**: Stage 2 qe 머신러닝 모델 학습(신규 데이터셋 확정 전 금지).
- **당장 제외(확장 구조 유지)**: 기체·액체 조성, 작용기 검출/분류, 기타 촉매 성능 예측.
- 웹 화면에서 모델을 새로 학습·조정하는 기능.
- 논문 PDF 자동 추출, 문헌 자동 검색, 실험 장비 연동, 후보 자동 생성·최적화.
- 실제 실험 결과나 전역 최적 조건을 보장하는 기능.
- 로그인·회원 관리 기능.

### 2.3 데이터와 역할의 구분

- **학습 데이터**: 과거 실험의 입력 조건, 실측 결과, 출처·실험 식별 정보를 포함한 자료.
- **예측 입력**: 결과를 모르는 후보 조건. 예측 대상값을 입력할 필요가 없다.
- **학습 담당자**: 입력·대상·검증 설정을 정하고 모델을 만드는 연구팀원.
- **웹앱 사용자**: 준비된 모델에 맞는 조건을 입력하고 결과를 확인하는 이용자.
- **측정값과 예측값의 구분**: Stage 2 입력으로 들어가는 BET·TPV는 실측값인지 Stage 1 예측값인지
  구분해야 하며, 예측값을 쓸 경우 오차 전파를 고려한다(연계 구조).
- Stage 1 은 원료 조성·열분해 조건만을 입력으로 한다. 활성화·함침·세척·반응기·분위기 등 모델에
  없는 인자를 고려한 것처럼 표시하지 않는다.

## 3. Stage 1 — 물성 예측 요구사항

### REQ-01. 데이터와 변수 설정 (유지·보강)

1. 학습 담당자가 지정한 파일·입력 열·목표 열에 따라 자료를 읽어야 한다.
2. 변수·단위를 바꿀 때 핵심 학습 코드 대신 계약·설정을 바꿀 수 있어야 한다.
3. 입력 변수, 예측 대상, 출처·분할용 식별 정보를 구분하고 식별 정보가 예측 입력에 섞이지 않아야 한다.
4. 입력별 자료형·단위·분석 basis와 대상의 정의·단위를 기록해야 한다.
5. 설정에 없는 열을 입력으로 자동 추가하거나 다른 열을 대상으로 추측해서는 안 된다.

### REQ-02. Stage 1 입력·출력 정의 (신규, v41 eval37 계약 기준)

1. Stage 1 BET 모델의 입력은 **10개**이며 순서·단위·분석 basis를 고정한다.
   - 원료 원소분석(**dry ash-free, daf**): C_pct, H_pct, N_pct, O_pct (wt%).
   - 원료 공업분석(**dry basis**): VM_pct, Ash_pct, FC_pct (wt%).
   - 열분해 조건: temperature_C(°C), time_min(min), heating_rate_C_min(°C/min).
2. 출력은 BET 비표면적(m²/g) 하나다. TPV(cm³/g)는 같은 입력 계약으로 별도 대상으로 둔다(보류).
3. 원료 조성과 생성 바이오차 조성을 혼동해서는 안 된다. C/H/N/O 합을 임의로 100으로 정규화해서는 안 된다.
4. 원소분석(daf)과 공업분석(dry basis)의 분석 기준이 다르다는 점을 기록하고 같은 숫자로 취급해서는 안 된다.
5. 초기 적용 범위는 **Leng2022 기반 비활성화(unmodified) 바이오매스 열분해**로 제한한다.

### REQ-03. 데이터 적격성과 점검 (유지·보강)

1. v41 패키지의 모든 CSV가 학습에 적합한 것은 아니다. **원자료·학습 후보·평가 자료·제외 자료·
   미검증 Stage 2 후보**를 구분해야 한다.
2. 결측·자료형 불일치·비유한 수치·중복 기록·출처 그룹 현황을 집계할 수 있어야 한다. 값을 생성하거나
   합계를 임의로 정규화해서는 안 된다.
3. 학습 적격 행과 부적격 행을 구분하되, 결측을 이유로 원본을 삭제하거나 임의 대체하지 않는다.
   추가 후보의 결측은 학습 파이프라인 내부의 정해진 결측 처리로만 다룬다.
4. 데이터 불러오기와 모델 학습은 별개 작업으로 구현한다.

### REQ-04. 모델 학습과 재현 (유지·보강)

1. Stage 1 BET 기준모델은 재현 가능한 **Random Forest**로 한다(n_estimators=300,
   min_samples_leaf=2, random_state=42, n_jobs=1). 학습 파이프라인 내부에서
   `SimpleImputer(strategy="median", add_indicator=True)`를 사용한다.
2. 모델 종류·하이퍼파라미터·데이터 버전(해시)·분할 설정·난수를 기록하여 재실행할 수 있어야 한다.
3. 학습과 앱 실행을 분리한다. 앱을 열 때마다 자동으로 재학습해서는 안 된다.

### REQ-05. 독립 평가와 출처 누설 방지 (유지·보강)

1. v41 `eval37/run.py`의 **GroupKFold 평가**(출처 그룹별 분할, 5-fold, seed 0/1/2, R²/MAE/RMSE)를
   우선 재현한다. 학습/검증 출처 중복 검사와 추가 후보의 동일·유사 관측값 혼입 검사를 포함한다.
2. 182행 기준 평가 데이터와 99행 추가 후보를 사용하되, 추가 후보를 평가 폴드에 무조건 병합하지 않고
   누설 방지 로직을 재현한다.
3. 기존 `eval37` 보고 결과를 **새 학습 모델의 독립 검증 결과처럼 과장하지 않는다.** 기존 검증을 먼저
   재현하고, 학습용 최종 모델의 저장·활성화는 별도 단계로 관리한다.
4. 실행 환경(라이브러리 버전)·분할 구현 차이가 있으면 그 차이를 보고한다.

### REQ-06. 모델 저장과 재사용 (유지)

1. 모델과 전처리를 함께 저장하고 학습 데이터 없이도 산출물로 예측할 수 있어야 한다.
2. 산출물은 모델 식별자·버전, 입력 열 이름·순서·자료형·단위·분석 basis, 대상 정의·단위를 포함해야 한다.
3. 산출물은 수치 입력의 학습 범위, 적용 범위 설명, 검증 결과 또는 미완료 상태, 라이브러리 버전,
   학습 시각, 데이터 버전 해시를 포함해야 한다.
4. 저장 후 다시 불러온 모델은 동일 입력에 대해 저장 전과 **일치하는 예측**을 제공해야 한다.
5. 모델·전처리·입력 규격의 버전이 맞지 않거나 필수 구성요소가 없으면 원인을 알리고 예측을 중단해야 한다.

### REQ-07. 적용 범위 검증 (유지·보강)

1. 입력값의 단위, 음수·비정상 조성, 원료 분석 basis, 학습 데이터 변수별 범위 이탈, 결측·사용 가능성을
   확인해야 한다.
2. 수치 입력이 학습 최솟값·최댓값을 벗어나면 어떤 변수가 벗어났는지 표시해야 한다(차단이 아닌 주의).
3. 물리적으로 허용되지 않는 조건(예: 질량% 범위 이탈, 음수)은 오류로 처리한다.
4. 변수별 범위 안에 있다는 사실만으로 모든 입력 조합이 충분히 검증됐다고 표시해서는 안 된다.
5. 외삽·지지 데이터 부족이 의심되면 경고를 표시하되, **검증되지 않은 신뢰도 백분율을 임의로 만들지
   않는다.** 학습 데이터와의 유사성·적용 조건 표시는 검증 모듈로 분리한다.

## 4. Stage 2 — 흡착성능 예측 요구사항 (확장 인터페이스)

### REQ-08. Stage 2 데이터 스키마와 학습 차단 (신규)

1. 향후 데이터 연결을 위해 다음 입력 항목을 수용하는 스키마와 검증 모듈을 설계한다: material_id,
   original_experiment_doi, feedstock 및 제조조건, measured_BET_m2_g, measured_TPV_cm3_g,
   pollutant, initial_concentration_mg_L, solution_pH, adsorbent_dose_g_L,
   adsorption_temperature_C, contact_time_min, equilibrium_concentration_mg_L, measured_qe_mg_g,
   equilibrium_verified, measurement_status, qa_status, provenance_group.
2. 스키마 정의는 모든 필드가 준비됐다는 뜻이 아니다. 데이터 확정 전에는 **머신러닝 모델을 학습하지
   않는다.**
3. 미검증(평형 미입증) qe는 자동으로 학습 대상으로 승인해서는 안 된다. 평형 검증 + measured 상태 +
   qe 수치 + 필수 필드가 갖춰진 행만 학습 승인 후보로 삼는다. 승인 행이 부족하면 학습을 차단한다.
4. **실측 qe / Langmuir qmax / 모델 예측값 / 미검증 reported capacity**를 구분해서 관리해야 한다.

### REQ-09. Stage 1 ↔ Stage 2 연계와 오차 전파 (신규, 목표로 문서화)

1. Stage 2 모델은 Stage 1과 **독립적으로** 학습·검증·저장할 수 있어야 한다.
2. Stage 1의 예측 BET/TPV를 Stage 2 입력으로 사용할 때는 **측정값과 예측값을 구분**하고 **오차 전파**를
   고려하도록 연결 구조를 분리한다.
3. 연계 예측 구조는 **최종 목표로 문서화**하되, 독립 검증 전에는 실제로 작동하는 성능 예측으로
   표시하지 않는다. 연계 평가 시 출처 누설 방지와 단계별 오차 구분이 전제다.

### REQ-10. Langmuir fitting (신규, 머신러닝과 구분)

1. 사용자가 동일 시료·동일 오염물질·동일 조건에서 측정한 여러 (Ce, qe) 쌍을 입력하면, 비선형
   최소제곱법으로 Langmuir 식 `qe = qmax·KL·Ce / (1 + KL·Ce)`를 피팅한다.
2. 출력: qmax(mg/g), KL(L/mg), 적합 곡선, 실측 점, 피팅 R²·RMSE.
3. 데이터가 부족하거나 피팅이 식별 불가능하면 결과를 생성하지 말고 사유를 출력한다.
4. 이 기능은 입력한 실측 등온흡착 데이터에 대한 피팅이며 **Stage 2 머신러닝 예측과 별개**임을 명시한다.

## 5. 예측 웹앱 요구사항

### REQ-11. 모델에 맞는 입력 화면과 조건 비교 (유지·보강)

1. 웹앱은 저장된 활성 모델을 불러오고 해당 규격에 맞춰 입력 항목을 구성한다. 예측 입력·파일 업로드가
   재학습을 일으켜서는 안 된다.
2. 사용자는 예측 전에 현재 모델·예측 지표·단위·검증 오차·적용 범위를 확인할 수 있어야 한다.
3. 동일 원료에서 열분해 온도 등을 변화시키는 조건 비교를 제공한다. 조건별 예측 비교표, 온도에 따른
   예측 곡선, CSV 결과 저장을 지원한다.
4. 조건 비교 그래프의 선은 **모델의 예측 응답**임을 표시하며 실제 측정 곡선처럼 표현해서는 안 된다.
5. 화면 구성은 연구실 공학 분석 소프트웨어처럼 기능 중심으로 한다(과도한 챗봇 스타일·광고성 카드·
   불필요한 애니메이션 배제).

### REQ-12. 단일·일괄 예측과 결과 표시 (유지)

1. 단일 조건 입력과 파일 일괄 입력에서 같은 모델·같은 조건은 같은 결과를 내야 한다.
2. 필수 값 누락·수치 해석 실패·지원하지 않는 입력은 문제 항목과 원인을 표시한다. 임의 보정으로
   통과시키지 않는다.
3. 결과에는 입력 조건·예측 지표·예측값·단위·모델 식별 정보를 함께 표시한다. 예시 숫자나 다른 모델의
   값을 정상 결과로 반환하지 않는다.
4. MAE·RMSE를 개별 예측의 신뢰구간이나 확정적 오차 상한으로 표현해서는 안 된다.

### REQ-13. 화면 결과 확인과 세션 분리 (유지)

1. 결과는 화면에서 확인한다. 조건 비교 CSV 저장은 사용자가 명시적으로 내려받는 다운로드 기능으로
   제공한다(Streamlit 데이터프레임의 자동 내보내기와 구분).
2. 여러 이용자의 입력·결과가 섞이거나 덮어써져서는 안 된다. 누적 이력·공통 기록은 제공하지 않는다.
3. 입력·파일·묶음 변경 시 이전 결과·순위를 무효화한다.

## 6. 보안·데이터 무결성 요구사항 (v1 유지)

### REQ-14. 데이터·모델 무결성

1. 실제 학습 자료·연구 기록·비밀값은 Git 저장소에 올리지 않는다(`data/`, `runs/`, `configs/local/`).
2. 모델 저장 산출물은 파일 무결성(해시)과 환경 호환성을 확인할 수 있어야 한다. 묶음 밖 경로·누락·훼손은
   오류로 처리한다.
3. 웹은 운영자가 저장소에 넣은 산출물만 읽는다. 이용자 업로드 파일·URL·경로를 모델 로딩에 사용하지 않는다.
4. 업로드 파일은 메모리에서 읽고 서버 영구 파일·공통 캐시에 저장하지 않는다. 로그에 입력값·예측값·원본
   표를 남기지 않는다.
5. 원본 zip·원본 데이터를 변경하지 않는다. 필요한 파일만 선택 추출하며 `eligible_for_training` 등
   원본 플래그를 변경하지 않는다.

## 7. 프로그램 완료와 연구 성능의 구분 (유지)

1. 프로그램 완료는 입력 처리, 학습·독립 평가, 모델 재사용, 단일·일괄 예측, 조건 비교, Stage 2 차단,
   Langmuir fitting이 지정된 방식대로 동작하는지로 판단한다.
2. 연구 성과는 독립 검증 오차·기준 모델 비교·적용 범위를 근거로 별도로 판단한다. 프로그램 완료가
   정확도·모든 지표 제공·전역 최적 조건을 뜻하지 않는다.
3. 예측값이나 성능 수치를 임의로 생성하지 않는다. 미검증 데이터를 추가하거나 기존 평가 점수 개선을
   위해 무리하게 알고리즘을 변경하지 않는다.

| 10 | 예측값이나 성능 수치를 임의로 생성하지 않는다. |
